# 서드 파티 스크립트를 추가할 때 발생할 수 있는 성능과 보안 위험은 무엇일까요?


> 서드 파티 스크립트는 방문자 분석, 광고 등에 유용하지만 과도하게 사용하면 네트워크 요청, 레더링 차단, 메인 스레드 점유와 같은 성능 저하와 XSS, 데이터 유출, 공급망 공격과 같은 보안 위험을 초래할 수 있습니다. 따라서 꼭 필요한 스크립트만 사용하고 async/defer 로딩, 신뢰할 수 있는 제공 업체 선택, CSP 설정, 정기적인 점검 등을 통해 위험을 최소화해야 합니다. 개발자는 기능 구현뿐 아니라 성능과 보안, 사용자 데이터 보호 책임을 함께 고려해야 합니다.


### 서드 파티 스크립트란?

1. <u>외부 서버에서 불러오는 작은 프로그램 코드</u>
	1. 구글 애널리틱스, 페이스북 픽셀, 각종 광고 네트워크 스크립트 등이 대표적인 예시
2. <u>방문자 분석, 광고 수익 창출, 고객 지원등 다양한 기능을 위해 사용한다.</u>
3. 서비스 운영에 큰 도움이 되지만 예상치 못한 문제를 발생시키기도 한다.

### 성능 저하의 위험

- 가장 먼저 체감되는 문제는 웹 사이트의 속도 저하.
	- 외부에서 불러오기에 편리하지만 성능에 부담이 되기도한다.
1. **네트워크 요청 증가**
	1. 외부 서버의 파일을 가져와야 함
	2. 해당 스크립트를 내려받기 위한 새로운 HTTP 요청이 발생
	3. 이 과정에서 DNS 조회, TCP 핸드셰이크, TLS 협상 등 여러 단계를 거쳐야 함
	4. 위 절차들은 웹 사이트 로딩 시간을 늘리는 직접적 원인이 된다.
	5. 예시
		1. 쇼핑몰 웹 사이트에 A, B 웹 사이트의 광고 스크립트 추가
		2. 사용자가 웹 사이트에 접속할 경우 쇼핑몰 서버 +
		광고 서버와도 각각 통신해야 함
		3. 이 과정에서 병목 현상이 발생하면 웹 사이트 전체 로딩이 지연
2. **렌더링 차단**
	1. 브라우저는 HTML 문서를 위에서 아래로 읽다가 `<script>` 태그를 만나면 스크립트를 내려받고 실행할 때까지 보통 페이지 렌더링을 멈춘다.
	2. 용량이 크거나 속도가 느린 서버의 스크립트가 `<head>` 태그 안에 있을 경우 사용자는 스크립트 로딩이 끝날 때 까지 빈 화면만 보게 될 수도 있다.
	3. 예시
		1. 구글 애널리틱스 추적 코드를 별다른 설정 없이 `<head>`에 넣었는데 해당 서버의 응답이 지연되면 웹 사이트의 내용이 표시되는 것 또한 함께 늦어질 수 있다.
3. **메인 스레드 점유**
	1. 내려받은 스크립트는 브라우저의 메인 스레드에서 실행된다.
	2. 메인 스레드는 사용자 클릭, 스크롤과 같은 인터랙션 처리, 화면 레이아웃 계산 등 핵심 작업을 담당한다.
	3. 만약 서드 파티 스크립트가 복잡한 연산을 수행하여 메인 스레드를 오랫동안 점유하면 스크롤이 끊기거나 버튼이 즉시 반응하지 않아 사용자는 웹 사이트가 멈췄다고 느끼게 된다.
	4. 예시
		1. 특정 고객 행동을 추적하고 서버로 전송하는 정교한 분석 스크립트를 추가했다면 메인 스레드의 부담이 커져 웹 사이트 전반적인 반응성이 떨어질 수 있다.

### 보안 취약의 위험

- 서드 파티 스크립트를 추가하는 것은 웹 사이트 일부 제어권을 외부 개발자와 공유하는 것과 같다.
	- 성능 저하보다 더 심각할 수 있는 보안 취약점 문제가 발생할 수 있다.
1. **XSS 공격 경로**
	1. 사용중인 서드 파티 스크립트 제공 서버가 해킹 된다면?
	→ 공격자는 정상적인 스크립트 코드에 악성 코드를 심어 배포할 수 있다.
	2. 웹 사이트는 그냥 평소처럼 스크립트를 불러왔지만 방문하는 모든 사용자의 웹 브라우저에 악성 코드가 실행되는 상황이 일어날 수 있다.
	3. 예시
		1. 라이브 채팅 솔루션 제공 업체와 서버가 해킹
		2. 채팅 스크립트 파일 끝에 사용자의 로그인 쿠키 정보를 탈취하여 공격자의 서버로 전송하는 악성 코드 추가
		3. 이 채팅 솔루션을 사용하는 모든 웹 사이트 방문자는 자신의 계정 정보를 탈취당함
2. **데이터 유출**
	1. 서드 파티 스크립트는 웹 사이트의 거의 모든 정보에 접근할 수 있다.
		1. 사용자가 입력하는 개인정보, 신용카드 번호 등 민감한 정보에도 접근 가능
	2. 악의적인 스크립트는 이 정보들을 몰래 외부 서버로 전송할 수 있다.
	3. 예시
		1. 웹 사이트에 설문조사 기능을 제공하는 서드 파티 스크립트를 추가함
		2. 이 스크립트가 설문 내용뿐만 아니라 배경에 있는 회원가입 폼의 사용자가 입력한 이름, 이메일, 비밀번호까지 감시하고 외부로 유출
3. **공급망 공격**
	1. 하나의 서드 파티 스크립트는 또 다른 서드 파티 스크립트를 불러올 수 있다.
		1. 신뢰했던 A 스크립트가 잘 알지 못하는 B 스크립트를, B 스크립트가 C 스크립트를 불러오는 연쇄적인 구조
	2. 이 연결 고리 중 단 하나만 해킹되어도 전체 서비스가 위험에 노출될 수 있다.
	3. 예시
		1. 구글 광고 스크립트를 추가
		2. 광고 최적화를 위해 여러 파트너사의 스크립트를 함께 볼러옴
		3. 이 중 보안이 취약한 한 파트너사의 서버가 악성 코드 유포지로 변질된다면
		4. 웹 사이트가 의도치 않게 악성 코드의 전달 경로가 됨

### 서드 파티 스크립트 안전하게 사용하기

- 아예 사용하지 않을 수는 없다.
	- 광고, 분석, 고객 지원 등 다양한 기능이 외부 스크립트에 의존하고 있기 때문
1. **반드시 필요한 스크립트만 사용하기**
	1. ‘이 기능이 정말 사용자 경험에 필수인가?’ 를 생각해보고 불필요한 스크립트는 과감히 제거
2. **비동기 또는 지연 로딩 사용하기**
	1. `<script>` 태그에 async 나 defer 속성을 추가하여 렌더링 차단을 줄이기
		1. **async**
			1. 스크립트 다운로드와 HTML 파싱이 동시에 진행되며 다운로드가 끝나면 즉시 실행
			2. 여러 스크립트가 있을 경우 실행 순서는 보장되지 않음
		2. **defer**
			1. 스크립트 다운로드와 HTML 파싱을 동시에 진행하지만 HTML 파싱이 모두 끝난 뒤 실행되므로 실행 순서가 보장됨
3. **신뢰할 수 있는 제공 업체 선택하기**
	1. 스크립트 제공 기업을 꼼꼼히 확인
	2. 검증되지 않은 출처의 스크립트는 사용하지 않는 것이 안전
4. **콘텐츠 보안 정책 설정하기**
	1. 웹 사이트에서 불러올 수 있는 스크립트의 도메인을 미리 지정해두기
5. **정기적인 감사와 모니터링 수행하기**
	1. 추가된 스크립트 목록을 정기적으로 검토
	2. 웹 사이트 성능 모니터링 도구를 사용하여 어떤 스크립트가 속도에 영향을 미치는지 지속적으로 확인
