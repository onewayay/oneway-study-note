# AWS (Amazon Web Services)

1. 개념
	1. 서버, 저장소, 데이터베이스 등 IT 인프라를 인터넷으로 빌려 쓰는 서비스
		1. = 내가 직접 컴퓨터 서버를 사지 않고, 아마존 컴퓨터를 빌려서 사용하는 것
2. 사용 이유
	1. 서비스를 운영하려면 서버가 필요함
		1. 실제 서버 컴퓨터 구매, 서버실 관리, 네트워크 설치, 유지보수 등이 필요
		2. 트래픽 갑자기 몰리면? 서버 추가 구매해야 함
	2. AWS를 사용하면?
		1. 서버 구매 X
		2. 관리 부담 감소
		3. 빠른 배포 가능
		4. 트래픽 몰리면? 클릭 몇 번으로 서버 늘림
		→ 쓴 만큼만 돈 냄
3. 클라우드란?
	1. 인터넷을 통해 IT 자원을 빌려쓰는 방식
	2. 서버, 데이터베이스, 파일 저장소, 네트워크, AI 서비스 듣을 온라인으로 제공
	3. ↔ 온프레미스 (On-premise)
		1. 내가 서버 직접 소유/관리
	4. AWS는 세계 최대의 클라우드 서비스임
4. 프론트엔드 개발자가 알아야할 핵심 서비스
	1. EC2 (Elastic Compute Cloud)
		1. 쉽게 말하면 인터넷으로 빌리는 컴퓨터(서버)
		2. 역할
			1. 가상의 컴퓨터 서버
			2. Node 서버 실행, Spring 서버 실행, nginx 설치, Docker 실행 등 가능
		3. 용도
			1. Node.js 서버 실행, Docker 컨테이너 실행 등
		4. 과금
			1. 켜놓은 시간만큼 돈 냄

		```typescript
		내 MacBook이랑 똑같은 컴퓨터인데
		→ AWS 데이터센터에 있고
		→ 24시간 켜져있고
		→ 인터넷으로 접근 가능한 것
		```

	2. S3 (Simple Storage Service)
		1. 파일 저장소 (구글 드라이브랑 비슷)
		2. 용도
			1. 이미지, 동영상, 파일 저장
			2. React 빌드 결과물(정적 파일) 올려서 웹사이트 호스팅
			3. 로그 파일 저장

			```typescript
			npm run build
			    ↓
			build/ 폴더 생성 (HTML, CSS, JS)
			    ↓
			S3에 업로드
			    ↓
			전 세계에서 접근 가능한 웹사이트 완성
			```

	3. CloudFront (CDN)
		1. S3랑 항상 같이 나오는 서비스
		2. CDN(Content Delivery Network)
			1. 전 세계 곳곳에 서버를 두고, 사용자와 가장 가까운 서버에서 파일을 전달하는 것
		3. 보통 S3 (파일 저장) + CloudFront (빠르게 전달) 세트로 사용

			```typescript
			S3만 쓸 때 (서버가 미국에만 있으면)
			한국 유저 → 미국 서버까지 파일 요청 → 느림
			
			CloudFront 쓸 때
			한국 유저 → 한국 CDN 서버에서 바로 전달 → 빠름
			```

	4. RDS (Relational Database Service)
		1. 데이터베이스를 빌려 쓰는 서비스
		2. 왜 사용하는가?
			1. EC2에 MySQL 직접 설치해서 쓸 수도 있지만
			→ 백업, 보안, 업데이트 직접 관리해야 함
			2. RDS 쓰면
			→ AWS가 다 알아서 관리해줌
			→ MySQL, PostgreSQL 등 선택해서 바로 사용 + 쉽게 운영 가능
	5. Route 53
		1. 도메인(주소) 관리 서비스
		2. 왜 사용하는가?
			1. AWS 서버 주소
				1. ec2-12-34-56-78.compute.amazonaws.com (못생김)
			2. Route 53 설정
				1. myapp.com (예쁨)
5. 프론트엔드 개발자가 AWS를 사용하는 대표적인 상황
	1. 프론트 프로젝트 배포
	2. 이미지 저장
	3. 백엔드 서버 운영
		1. API 서버, DB 서버, 인증 서버 등이 AWS 위에서 돌아감.
