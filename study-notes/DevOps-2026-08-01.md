# DevOps

1. 개념
	1. 개발(Development)과 운영(Operations)이 협력해서 소프트웨어를 더 빠르고 안정적으로 만들고 배포하는 문화/방법론
	2. 빠른 변화를 원하는 개발팀 + 안정성을 원하는 운영팀
2. 장점
	1. 속도
		1. 작업 속도가 빨라지면서 시장 변화에 더 잘 적응하고 효율적으로 비즈니스 성과를 창출 가능
	2. 신속한 제공
		1. 새로운 기능의 릴리스와 버그 수정 속도가 빨라질수록 경쟁 우위 차지 가능
		2. 릴리스란?
			1. 개발된 프로그램, 앱, 업데이트를 사용자에게 공식적으로 출시하거나 배포하는 것
	3. 안정성
		1. 애플리케이션 업데이트와 인프라 변경의 품질 보장, 지속적 통합 및 지속적 전달과 같은 방식을 통해 변경 사항이 제대로 안전하게 작동하는지 테스트 가능
	4. 확장 가능
		1. 규모에 따라 인프라와 개발 프로세스 운영, 관리 가능
	5. 협업 강화
		1. 개발자와 운영 부서간의 협력을 통한 효과적인 팀 구축 가능
	6. 보안
		1. 자동화된 규정 준수 정책, 세분화된 제어 및 구성 관리 기술 사용 가능
3. DevOps의 주요 실천 방법
	1. CI, CD, CT
		1. 코드 변경 → 자동 테스트 → 자동 배포
		2. 지속적 통합(CI)와 지속적 배포(CD), 지속적 테스트(CT)를 통해 빠르고 안정적인 배포를 가능하게 함
	2. 인프라 as 코드(IaC)
		1. 서버 설정을 코드로 관리
		2. 예전: 서버에 직접 접속해서 손으로 설정
		지금: 코드로 서버 환경을 정의 → 자동으로 구축
		3. 도구
			1. Terraform, AWS CloudFormation
	3. 지속적 모니터링(CM)
		1. 배포 후 서버 상태, 에러, 성능을 실시간으로 감시
		2. "배포했더니 에러율이 갑자기 올라갔다"
		→ 즉시 감지하고 대응
		3. 도구
			1. Datadog, Grafana, AWS CloudWatch
	4. 컨테이너화
		1. Docker로 어디서든 동일한 환경 보장
		→ "내 컴퓨터에선 됐는데 서버에서 안 돼요" 방지
4. DevOps 엔지니어가 하는 일
	1. CI/CD 파이프라인 구축/관리
	2. 서버 인프라 설계 (AWS 등)
	3. Docker, 쿠버네티스로 컨테이너 관리
	4. 모니터링 시스템 구축
	5. 보안 설정
5. 프론트엔드 개발자와의 관계
	1. 직접 DevOps를 담당하진 않지만 협업하는 상황이 생긴다.
	2. 예시
		1. "빌드가 CI에서 실패해요" → GitHub Actions 로그 볼 줄 알아야 함
		2. "배포 환경 변수 설정이 필요해요" → DevOps팀에 요청할 줄 알아야 함
		3. "Dockerfile 작성해주세요" → 기본 개념은 알아야 함
