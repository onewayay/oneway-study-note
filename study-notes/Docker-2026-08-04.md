# Docker

1. Docker 란?
	1. Docker는 앱 실행에 필요한 환경을 컨테이너로 패키징해서, 어떤 환경에서도 동일하게 실행될 수 있도록 보장하는 도구
	2. “내 컴퓨터에서는 잘 되는데요?" 해결

		```javascript
		개발자 A 컴퓨터  →  Node.js 18 버전, 잘 됨
		개발자 B 컴퓨터  →  Node.js 16 버전, 안 됨
		실제 서버        →  Node.js 14 버전, 안 됨
		```

		1. 위처럼 환경이 달라서 생기는 문제를 Docker를 사용해서 "실행 환경 자체를 통째로 포장해서 어디서든 똑같이 실행" 되게 해줌
	3. 질문
		1. node 버전은 어쩔수 없다 치고 라이브러리 등등은 package.json을 통해 환경을 맞출수 있지 않을까?
		2. 답
			1. Docker가 해결하는 환경 문제는 Node 버전만이 아님
				1. Node.js 버전, OS 종류 (Mac / Windows / Linux), OS 버전, 시스템 환경변수, 포트 설정, DB 버전 (MySQL 8.0 vs 5.7), 캐시 서버 버전 (Redis 버전)
			2. 특히 백엔드랑 같이 개발할 때 문제가 커짐
				1. 프론트엔드  →  package.json으로 어느 정도 해결
				2. 백엔드      →  Node 버전 + DB + Redis + 환경변수 + OS... 다 맞춰야 함
2. 핵심 개념
	1. 컨테이너 (Container)
		1. 앱 실행에 필요한 모든 것(코드, 런타임, 라이브러리)을 하나로 묶은 패키지

		```javascript
		컨테이너 안에
		├── 내 앱 코드
		├── Node.js 18
		├── 필요한 라이브러리
		└── 환경변수 설정
		```

		1. 어디서 실행해도 이 안에 다 들어있으니까 환경이 달라도 똑같이 동작
		2. 이미지를 실제 실행한 상태
	2. 이미지 (Image)
		1. 컨테이너를 만들기 위한 설계도 / 틀
		2. 이미지 하나로 컨테이너 여러 개 만들 수 있음
			1. 붕어빵 틀 같은 개념
		3. 예시

			```javascript
			node:20
			nginx
			mysql
			```

	3. Dockerfile
		1. 이미지를 어떻게 만들지 정의하는 레시피 파일

		```javascript
		FROM node:18          ← Node.js 18 환경에서 시작
		WORKDIR /app          ← 작업 폴더 설정
		COPY . .              ← 내 코드 복사
		RUN npm install       ← 라이브러리 설치
		CMD ["npm", "start"]  ← 실행 명령어
		```

	4. Docker Hub
		1. 이미지를 저장하고 공유하는 저장소 (GitHub의 이미지 버전)
3. VM(가상머신)과의 차이
	1. VM (가상머신)
		1. 구조
			1. OS 전체를 가상화
		2. 용량
			1. 수 GB
		3. 시작 속도
			1. 수 분
		4. 성능
			1. 상대적으로 느림
	2. Docker (컨테이너)
		1. 구조
			1. OS는 공유, 앱만 격리
		2. 용량
			1. 수 MB ~ 수백 MB
		3. 시작 속도
			1. 수 초
		4. 성능
			1. 빠름

### ③ Dockerfile 작성


프로젝트 루트에 `Dockerfile` 파일 생성 (확장자 없음)


```javascript
my-docker-app/
├── src/
├── public/
├── package.json
├── node_modules/
└── Dockerfile   ← 여기
```


Dockerfile 내용


```docker
# 1. 베이스 이미지 설정 (Node.js 18 환경)
FROM node:18

# 2. 컨테이너 안에서 작업할 폴더 지정
WORKDIR /app

# 3. package.json 먼저 복사 (캐싱 최적화)
COPY package.json .

# 4. 라이브러리 설치
RUN npm install

# 5. 나머지 소스코드 전부 복사
COPY . .

# 6. 앱 실행
CMD ["npm", "start"]
```


각 줄이 하나의 레이어가 돼요. `package.json`을 먼저 복사하는 이유는, 소스코드가 바뀌어도 라이브러리는 다시 설치 안 하게 하려고요 (캐싱).

### ④ .dockerignore 작성


`.gitignore`처럼 Docker 이미지에 포함하지 않을 파일 지정


```javascript
my-docker-app/
└── .dockerignore   ← 여기
```


```javascript
node_modules
build
.env
```


`node_modules`는 컨테이너 안에서 새로 설치할 거라 제외해요.

### ⑤ 이미지 빌드


```bash
# 터미널에서 프로젝트 루트에서 실행
docker build -t my-docker-app .
#            ↑ 이미지 이름    ↑ 현재 폴더의 Dockerfile 사용
```


빌드 과정이 터미널에 출력돼요


```javascript
Step 1/6 : FROM node:18
Step 2/6 : WORKDIR /app
Step 3/6 : COPY package.json .
Step 4/6 : RUN npm install
Step 5/6 : COPY . .
Step 6/6 : CMD ["npm", "start"]
Successfully built abc123
```


이미지 확인


```bash
docker images
# REPOSITORY       TAG      IMAGE ID
# my-docker-app    latest   abc123
```

### ⑥ 컨테이너 실행


```bash
docker run -p 3000:3000 my-docker-app
#          ↑ 포트 연결
#          내 컴퓨터 3000 : 컨테이너 안 3000
```


브라우저에서 `localhost:3000` 접속하면 React 앱이 떠요.

### ⑦ 자주 쓰는 명령어


```bash
# 실행 중인 컨테이너 목록

# 모든 컨테이너 목록 (멈춘 것 포함)

docker exec -it [컨테이너ID] /bin/sh
```

### ⑧ docker-compose (DB랑 같이 띄우기)


실제 프로젝트에선 앱 + DB를 같이 띄워야 해요. 이때 `docker-compose`를 써요.


프로젝트 루트에 `docker-compose.yml` 생성


```javascript
my-docker-app/
└── docker-compose.yml   ← 여기
```


yaml


```yaml
version: '3'
services:
  app:                      # 내 React 앱
    build: .
    ports:
      - "3000:3000"

  db:                       # MySQL DB
    image: mysql:8.0        # Docker Hub에서 MySQL 이미지 가져옴
    environment:
      MYSQL_ROOT_PASSWORD: password
      MYSQL_DATABASE: mydb
    ports:
      - "3306:3306"
```


실행


```bash
# 전부 한번에 띄우기
docker-compose up

# 백그라운드로 실행
docker-compose up -d

# 전부 내리기
docker-compose down
```


명령어 하나로 앱이랑 DB가 동시에 실행돼요.
