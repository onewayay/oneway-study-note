# CI/CD 파이프라인

1. 개념
	1. 소스 코드 수정부터 빌드, 테스트, 배포까지 전 과정을 자동화하여 소프트웨어를 빠르고 안정적으로 제공하는 기술
	2. 사람이 수동으로 할 때보다 실수를 줄이고, 자동화로 빠르게 작업

	```javascript
	개발자가 코드 푸시
	    ↓
	자동으로 테스트 실행
	    ↓
	자동으로 빌드
	    ↓
	자동으로 서버에 배포
	```

2. **CI** (Continuous Integration, 지속적 통합)
	1. 여러 개발자가 작성한 코드를 **자주, 자동으로 합치고 검증**하는 것
	2. 역할
		- 코드 스타일 검사 (ESLint)
		- 단위 테스트 실행
		- 빌드가 잘 되는지 확인
3. **CD** (Continuous Delivery/Deployment, 지속적 배포)
	1. CI를 통과한 코드를 **자동으로 서버에 올리는** 것
	- **Continuous Delivery**: 배포 준비까지 자동, 실제 배포는 사람이 버튼 클릭
	- **Continuous Deployment**: 배포까지 100% 자동
4. 주요 CI/CD 도구
	- **GitLab CI/CD**
		- 리포지토리 관리와 파이프라인 기능이 내장되어 인기가 높음
	- **Jenkins**
		- 다양한 플러그인을 제공하는 오픈소스 자동화 서버
		- 커스터마이징 자유로움
	- **GitHub Actions**
		- GitHub에 내장된 클라우드 기반 CI/CD
		- CI/CD 말고도 다양한 자동화에 쓰임
		→ 일련의 파이프라인을 설정 가능
	- **AWS CodePipeline**
		- AWS 인프라에 최적화된 관리형 서비스
	- Vercel / Netlify
		- 프론트엔드 특화. PR 올리면 자동 배포
5. 파이프라인
	1. 파이프라인이란?
		1. 특정 이벤트가 발생했을 때, 정해진 작업들을 순서대로 자동 실행하는 흐름
		2. 예) Push 발생 → 린트 검사 → 테스트 → 빌드 → 배포
	2. 파이프라인 예

		```javascript
		① 코드 작성
		② GitHub에 Push / PR 생성
		③ [CI] 린트 → 테스트 → 빌드
		④ 코드 리뷰 & Merge
		⑤ [CD] 스테이징 배포 → 확인 → 프로덕션 배포
		```
